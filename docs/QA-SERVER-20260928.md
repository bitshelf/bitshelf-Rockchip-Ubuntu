# RK3576 Ubuntu Server 板端验收（2026-09-28）

目标板为 MYIR MYD-LR3576，USB 刷机主机为 `linaro@192.168.1.105`。使用
`upgrade_tool v2.44` 对唯一 Loader 设备（USB LocationID 3113）执行 `UF`。
镜像是 `output/ubuntu-server-20260922/factory/Image/update.img`，9 月 28 日
重新封装，SHA256：

```text
5c511ef8fe72e7cf3c1cd8427e68576c9ab04fc9e44bc182e168140c76a2da0a
```

`upgrade_tool` 返回 `Download Firmware Success`、`Upgrade firmware ok.`。
板上启动 Ubuntu 26.04.1、内核 `6.1.118-rt36`；`/boot` 为 ext4，
只读 rootfs 为 EROFS，持久层为 ext4 userdata。首次启动无预置用户、root 锁定；
首启引擎创建普通管理员后，重启不再要求建号。测试板账户密码由现场设置，
不属于镜像默认凭据。

| 验收项 | 板端结果 |
| --- | --- |
| 首次启动有线网络 | `end0` 获得 DHCP 地址和默认路由，DNS 与直连 HTTPS 通过 |
| 第二次启动有线网络 | 同样通过；`systemd-networkd`、`systemd-resolved` 正常 |
| SSH | 普通管理员密码登录通过 |
| systemd 失败单元 | 0 |
| MPP H.264 | 硬件编码、解码各 100 帧通过 |
| GStreamer MPP | 编码、解码 100 帧并到达 EOS |
| V4L2 包装层 | `/dev/video-dec0` 能通过 libv4l-rkmpp 查询 |
| ALSA CLI | 2 张卡、2 路播放、1 路录音、6 个控制项 |
| updateEngine | 只读 BCB 检查通过，misc 哈希和 boot ID 不变 |
| HDMI | connector 状态为 `unknown`，未证明有画面输出 |

原始刷机、串口和命令日志保存在 SDK 工作区的
`output/ubuntu-server-20260922/server-*.log`；结构化结果见
`docs/qa/server-20260928.json`。此次验收使用现成 Server rootfs 构建产物及
9 月 28 日重新封装的镜像，未从当前提交重新执行完整 rootfs 构建。

启动日志仍有未接设备相关的 PCIe、摄像头探测消息，以及 CMA 分配消息；
它们没有造成上述验收失败。HDMI 问题仍需在显示功能验收中单独定位。
